# 願景與路線圖

## 願景
用同一套方法，做出能感知、建圖、行動的機器人家族：

- 小鴨（雙足）：學習與訓練平台，並與全世界一起訓練
- 無人車：在家自主巡邏、視覺避障、自動充電
- 3D 建模：與電腦配合，畫出家的 3D 模型
- 之後擴展：無人機、潛水艇、自製聲納、光達系統

## 核心判斷
這些目標本質上是同一條線：**感測 → 建圖 → 規劃 → 行動**。所以先做共用平台，載具再逐台更換。

### 小鴨的角色
Open Duck Mini 是學習和展示用的小型雙足機器人。它的運算板（Pi Zero 2 W，512 MB）跑不動 SLAM 與視覺，雙足也不適合自動充電對位。因此**小鴨不承擔巡邏和建圖**，由輪式無人車與獨立的感測模組承擔。

## 系統架構：本體 + 遠端大腦
家中 WiFi 連線，桌機（RTX 4090）做視覺與規劃，本體只做即時控制與安全。

```
本體（機器人）                        大腦（4090 主機）
──────────────                        ─────────────────
馬達／平衡迴圈（高頻）                 影像解碼
IMU、輪速／關節回授                    深度估計、物件偵測、SLAM
緊急停止：近距感測、碰撞、斷線看門狗    路徑規劃、視覺語言模型
相機編碼並串流  ─────── WiFi ───────▶  地圖與 3D 模型
接收速度指令／路徑點  ◀────────────    以 5–20 Hz 送出指令
```

### 設計原則
1. **即時且攸關安全的迴圈留在本體。** 平衡、馬達控制、避碰急停不能依賴 WiFi。
2. **大腦只下高階指令**（速度、路徑點），不直接控制馬達。小鴨的走路策略本來就以速度指令為輸入，剛好是自然的切點。
3. **斷線就停。** 本體有看門狗，超過設定時間沒收到指令，自動減速並停止。
4. **影像串流要低延遲。** 用硬體編碼 H.264／WebRTC，不傳原始影像。
5. **先在模擬與近距離驗證**，再放到全屋。

### 已知限制
- Pi Zero 2 W 只支援 2.4 GHz WiFi，擁擠環境延遲抖動大。巡邏載具要用能支援 5 GHz 的運算板。
- WiFi 延遲偶爾會尖峰到百毫秒級，所以才要把急停放在本體。

## 階段路線圖
| 階段 | 目標 | 驗收標準 |
|---|---|---|
| 0 | 小鴨走路主線：買零件、列印、組裝、測試；Microduck 模擬訓練；CAD 骨架 | 小鴨在平地依速度指令走 10 m 不跌倒 |
| 1 | 感測模組 + 手持建圖：光達／深度相機 + 4090 離線建圖 | 掃描一個房間，產出可檢視的 3D 網格，並與捲尺實測比對 |
| 2 | 輪式無人車：底盤、電源、本體控制、近距避障、WiFi 遙控 | 遙控巡過一個房間，遇障礙自動停 |
| 3 | 遠端大腦整合：視覺避障、自主巡邏、斷線看門狗 | 無人介入完成一圈巡邏，斷線時停下 |
| 3.5 | 自動充電：充電座與對位 | 電量低時自行回座並開始充電 |
| 4 | 無人機 | 先確認法規與安全，再決定範圍 |
| 5 | 潛水艇與自製聲納 | 先做防水與感測測試，再整合 |

## 規則
- 每個階段都要有驗收標準，達到才進下一階段。
- 每台新載具都先重用共用平台，缺什麼補什麼，補完回饋平台。
- 無人機與水下項目，動手前先查台灣法規與安全要求。

## 割草機與車載無人機（構想，2026-11-19）
- 割草機（四輪、RTK、手機視覺）與無人機勘查協作：無人機從車上起飛，看全局後降回車上，割草機再繼續工作。
- 開發方式：**CAD 一起畫，各自分開訓練，最後組合。**
- 先固定的介面（兩邊都要遵守）：降落板尺寸與標記、座標系（RTK 經緯度轉本地座標）、地圖格式、共同意圖介面（docs/07）。
- 分階段：① 無人機獨立勘查、手動起降 ② 割草機只用地面感測器照地圖工作 ③ 車頂加降落板，手動起降 ④ 自動起降與自動勘查。
- 前置：台灣無人機註冊與飛行規定、階梯在邊界內外、安全層（懸崖、碰撞、傾斜、急停）。細節見 hardware/mower/README.md。
