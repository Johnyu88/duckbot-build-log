# 06 · Microduck 機上軟體：可借用到 Open Duck 與無人車的設計

來源：`pollen-robotics/microduck`（Rust，Apache-2.0）的 `README.md` 與 `docs/design/`。
讀取日期 2026-11-19。這份是讀文件整理的對照，**沒有在實機或我們的硬體上驗證**。

## 1. 它的架構（一句話版）

一塊主板上 8 個小程式（daemon），透過 Unix socket 說同一套 JSON-RPC。**只有 `robotd` 能碰馬達**，其他都只能送「意圖」（走多快、看哪裡、站起來），由 `robotd` 的安全層決定能不能做。

| 程式 | 負責 | 我們可借用的概念 |
|---|---|---|
| `robotd` | 50 Hz 控制迴圈、匯流排、策略、安全、健康回報 | 單一程式獨佔馬達；其他人只送意圖；deadman（失聯自動停） |
| `btd` | 藍牙通道，只開放 API 的子集 | 手機設定走藍牙，沒網路也能改 wifi、更新、看健康 |
| `padd` / `netpadd` | 搖桿（藍牙／區網 UDP）轉成同樣的意圖 | 搖桿與 App 共用同一套呼叫，不各寫一套 |
| `mediad` | 相機 H.264 經 WebRTC 串流，另有資料通道傳控制 | 影像低延遲傳到桌機；控制走同一條通道 |
| `tofd` | 頭部 8×8 深度感測，只發布 | 感測器程式只輸出資料，不收指令 |
| `autod` | 自主行為（追雷射點、避障），一般的意圖客戶端 | 「大腦」與馬達分離；可隨時殺掉，機器人自己停 |
| `mapd` | 地圖與定位 | 見第 3 節 |
| `configd` / `updaterd` | 設定、wifi、簽章更新與回滾 | 更新失敗自動回到舊版 |

## 2. 對我們「本體加遠端大腦」架構的意義

我們的設計是本體跑即時與安全迴圈、4090 桌機跑感知與規劃。Microduck 的作法與它一致：

- **大腦是普通客戶端。** `autod` 和搖桿、App 發出同樣的意圖，沒有特權。桌機上的 AI 程式也可以只當另一個客戶端，送 `move`、`head` 這類意圖。
- **安全留在機上。** 失聯時由 deadman 停止機器人。我們的遠端大腦走 WiFi，一定要有同樣機制（本體多久沒收到指令就自己站穩或停下）。
- **兩條傳輸並行。** 藍牙：永遠能用，負責設定。WebRTC：快，負責影像與駕駛。藍牙先告訴你要連哪個 IP。
- **單一契約。** 所有客戶端用同一套 JSON-RPC。我們定義自己的介面時，也先寫成一份清單，再讓 App、搖桿、AI 都照它呼叫。

## 3. 建圖的現實限制（對我們的 3D 建圖目標很重要）

Microduck 官方文件自己寫：頭部 8×8 ToF 是「手杖，不是光達」，有效距離多在 0.4–0.6 m，並且說在這個平台上視覺里程計不可行。他們的做法是用腿部接觸里程計加 IMU 陀螺儀積分，只建二維平面圖。

這支持我們原本的決定：**巡邏與建圖交給有輪子的無人車加獨立感測模組**（光達或深度相機），小鴨當學習與吉祥物平台。

## 4. 可以直接拿來做的事

1. **Open Duck 的遙控**：Open Duck 沒有手機 App。可照 `netpadd` 的做法，用 UDP 送搖桿狀態，或做簡單網頁。
2. **意圖介面清單**：先列出 `move / head / stand / sit / enable / relax / health` 等呼叫，當作我們所有機器人的共同語言。
3. **桌機 CLI**：`duckctl` 可從筆電經藍牙操作機器人，不需網路與 ssh，我們的機器人也值得有一支。
